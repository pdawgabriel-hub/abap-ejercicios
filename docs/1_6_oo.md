# 1.6. Clases y objetos (ABAP OO)

{% raw %}
`ZCL_TL_CALCULOS` es una clase sin estado: cada método recibe todo lo que necesita y devuelve un resultado. Pero hay cosas que **tienen estado**: un presupuesto va acumulando partidas y pasa de borrador a aceptado, y un mecánico tiene una tarifa que puede cambiar. Para eso están los **objetos**. En esta unidad los vemos con el mecánico y el registro de jornada del taller, y con ellos una decisión de diseño importante: **la tarifa se congela en cada tramo**. Tú modelarás el trabajador, el presupuesto y el parte de trabajo del ERP, con la misma regla (§11.5, punto 3).

## Clases y objetos

Una **clase** es la plantilla; un **objeto** es una instancia concreta, creada con `NEW`. Cada objeto tiene sus propios valores en los **atributos** de instancia (`DATA`). Los métodos de instancia (`METHODS`) trabajan con esos valores; los estáticos (`CLASS-METHODS`) no tienen objeto.

```abap
CLASS zcl_tl_mecanico DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS constructor
      IMPORTING iv_ref    TYPE zif_tl_tipos=>ty_ref
                iv_tarifa TYPE zif_tl_tipos=>ty_euros DEFAULT 30.
    METHODS ref
      RETURNING VALUE(rv_ref) TYPE zif_tl_tipos=>ty_ref.
    METHODS tarifa
      RETURNING VALUE(rv_tarifa) TYPE zif_tl_tipos=>ty_euros.
    METHODS revisar_tarifa
      IMPORTING iv_nueva TYPE zif_tl_tipos=>ty_euros.
  PRIVATE SECTION.
    DATA mv_ref    TYPE zif_tl_tipos=>ty_ref.
    DATA mv_tarifa TYPE zif_tl_tipos=>ty_euros.
ENDCLASS.

CLASS zcl_tl_mecanico IMPLEMENTATION.
  METHOD constructor.
    mv_ref    = iv_ref.
    mv_tarifa = iv_tarifa.
  ENDMETHOD.

  METHOD ref.
    rv_ref = mv_ref.
  ENDMETHOD.

  METHOD tarifa.
    rv_tarifa = mv_tarifa.
  ENDMETHOD.

  METHOD revisar_tarifa.
    mv_tarifa = iv_nueva.
  ENDMETHOD.
ENDCLASS.
```

- **Secciones de visibilidad.** `PUBLIC SECTION` es lo que se puede usar desde fuera; `PRIVATE SECTION`, lo que solo usa la propia clase. Entre ambas está `PROTECTED SECTION`, visible también para las subclases. Los atributos son privados y se leen con métodos: así la clase controla cómo cambian.
- **`constructor`** se ejecuta al crear el objeto. `DEFAULT 30` es la tarifa base del taller, que se aplica si no se indica otra.
- **Prefijos:** `mv_` para los atributos (*member value*), `mt_` para las tablas que son atributos, `lo_` e `io_` para las referencias a objetos.

## Crear y usar objetos

```abap
    DATA(lo_rosa)  = NEW zcl_tl_mecanico( iv_ref = 'MEC0001' ).
    DATA(lo_diego) = NEW zcl_tl_mecanico( iv_ref = 'MEC0002' iv_tarifa = 35 ).

    out->write( lo_rosa->tarifa( ) ).     " 30
    lo_rosa->revisar_tarifa( 32 ).
    out->write( lo_rosa->tarifa( ) ).     " 32
```

`NEW` crea el objeto y devuelve una **referencia** a él (`TYPE REF TO zcl_tl_mecanico`). Los métodos de instancia se llaman con `->`; los estáticos, con `=>`. Dentro de la propia clase, `me->` se refiere al objeto actual (como `self` en Python); casi siempre se puede omitir.

## Referencias y copias

Una variable de referencia **no contiene el objeto**: apunta a él. Si copias la referencia, las dos variables apuntan al mismo objeto:

```abap
    DATA(lo_misma) = lo_rosa.
    lo_misma->revisar_tarifa( 40 ).
    out->write( lo_rosa->tarifa( ) ).     " 40: es el mismo objeto
```

Los valores simples y las estructuras, en cambio, **se copian**. Esta diferencia es la que resuelve la tarifa congelada:

- Si el tramo guardara una **referencia** al mecánico y leyera su tarifa al calcular, revisar la tarifa cambiaría todas las jornadas antiguas.
- Si el tramo **copia** la tarifa al anotarse, las jornadas antiguas no cambian.

## Objetos que usan otros objetos

El registro de jornada recibe el mecánico como objeto, pero en el tramo guarda solo su referencia de código y una **copia** de su tarifa:

```abap
CLASS zcl_tl_jornada DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS add_tramo
      IMPORTING io_mecanico TYPE REF TO zcl_tl_mecanico
                iv_tiempo   TYPE zif_tl_tipos=>ty_tiempo.
    METHODS coste
      RETURNING VALUE(rv_coste) TYPE zif_tl_tipos=>ty_euros.
    METHODS tramos
      RETURNING VALUE(rt_tramos) TYPE zif_tl_tipos=>tt_tramos.
  PRIVATE SECTION.
    DATA mt_tramos TYPE zif_tl_tipos=>tt_tramos.
ENDCLASS.

CLASS zcl_tl_jornada IMPLEMENTATION.
  METHOD add_tramo.
    APPEND VALUE #( mecanico        = io_mecanico->ref( )
                    tiempo          = iv_tiempo
                    tarifa_aplicada = io_mecanico->tarifa( ) ) TO mt_tramos.
  ENDMETHOD.

  METHOD coste.
    rv_coste = zcl_tl_calculos=>coste_jornada( mt_tramos ).
  ENDMETHOD.

  METHOD tramos.
    rt_tramos = mt_tramos.
  ENDMETHOD.
ENDCLASS.
```

Fíjate en que `coste` **no repite la fórmula**: llama a `coste_jornada`, de `ZCL_TL_CALCULOS`. Cada regla está escrita una sola vez, y los objetos la usan.

## Estado que cambia: aceptar un presupuesto

Un atributo puede guardar en qué situación está el objeto. El presupuesto del taller empieza en borrador y cambia al aceptarlo:

```abap
  PRIVATE SECTION.
    DATA mv_situacion TYPE zif_tl_tipos=>ty_situacion
                      VALUE zif_tl_tipos=>situacion_presupuesto-borrador.
...
  METHOD aceptar.
    mv_situacion = zif_tl_tipos=>situacion_presupuesto-aceptado.
  ENDMETHOD.

  METHOD esta_aceptado.
    rv_aceptado = xsdbool( mv_situacion = zif_tl_tipos=>situacion_presupuesto-aceptado ).
  ENDMETHOD.
```

`VALUE` en la declaración del atributo da su valor inicial. `xsdbool( condición )` convierte una condición en `abap_bool`.

## Preparación del entorno de trabajo

Las tres clases nuevas del ERP van en `ZGOR_BUS`, junto a `ZCL_GOR_REGLAS`; la clase de pruebas, en `ZGOR_TEST`. Al terminar:

```
ZGOR_BUS
├── ZIF_GOR_TIPOS, ZCL_GOR_REGLAS     (1.2 a 1.4)
├── ZCL_GOR_TRABAJADOR                ← nueva
├── ZCL_GOR_PRESUPUESTO               ← nueva
└── ZCL_GOR_PARTE_TRABAJO             ← nueva
ZGOR_TEST
└── ZCL_GOR_OO_DEMO                   ← nueva
```

## Ejercicios

1. **El trabajador.** Crea `ZCL_GOR_TRABAJADOR` con dos atributos privados (el código, `ty_codigo`, y el coste por hora, `ty_importe`) y estos métodos públicos:

    | Método | Firma | Qué hace |
    |---|---|---|
    | `constructor` | `iv_codigo` (`ty_codigo`), `iv_coste_hora` (`ty_importe`, por defecto **20**, la tarifa habitual de §3.2) | Guarda los dos valores |
    | `get_codigo` | Devuelve `rv_codigo` (`ty_codigo`) | |
    | `get_coste_hora` | Devuelve `rv_coste` (`ty_importe`) | |
    | `set_coste_hora` | Recibe `iv_coste_hora` (`ty_importe`) | Cambia la tarifa |

2. **El presupuesto.** Crea `ZCL_GOR_PRESUPUESTO`, con el IVA, las líneas (`tt_presu_lineas`) y el estado como atributos privados. El estado empieza en `no_aprobado`.

    | Método | Firma | Qué hace |
    |---|---|---|
    | `constructor` | `iv_iva` (`ty_porcentaje`, por defecto **21**) | Guarda el IVA |
    | `add_linea` | `iv_descripcion` (`string`), `iv_uds` (`i`), `iv_precio` (`ty_importe`) | Añade una línea |
    | `get_lineas` | Devuelve `rt_lineas` (`tt_presu_lineas`) | |
    | `base`, `cuota`, `total` | Devuelven `rv_base`, `rv_cuota`, `rv_total` (`ty_importe`) | Con `base_imponible`, `cuota_iva` y `total_presupuesto` de `ZCL_GOR_REGLAS`, sin repetir ninguna fórmula |
    | `aprobar`, `desaprobar` | — | Cambian el estado |
    | `esta_aprobado` | Devuelve `rv_aprobado` (`abap_bool`) | |

3. **El parte de trabajo.** Crea `ZCL_GOR_PARTE_TRABAJO`, con las líneas (`tt_parte_lineas`) como atributo privado:

    | Método | Firma | Qué hace |
    |---|---|---|
    | `add_linea` | `io_trabajador` (`REF TO zcl_gor_trabajador`), `iv_horas` (`ty_horas`) | Añade una línea con el código y una **copia** de la tarifa del trabajador |
    | `horas_totales` | Devuelve `rv_horas` (`ty_horas`) | Con `horas_parte` |
    | `coste_total` | Devuelve `rv_coste` (`ty_importe`) | Con `coste_parte` |
    | `get_lineas` | Devuelve `rt_lineas` (`tt_parte_lineas`) | |

4. **El escenario, pasos 2 y 3.** Crea la clase ejecutable `ZCL_GOR_OO_DEMO`. Crea un presupuesto con una línea de 10 uds a 100 € y escribe su base, cuota y total (1000 / 210 / 1210) y si está aprobado (no). Apruébalo y vuelve a escribir el estado.
5. **El escenario, pasos 4 y 5.** Crea dos trabajadores a 20 €/h y un parte con 8 h de cada uno: el parte suma **16 h y 320 €**. Sube la tarifa del primero a 25 €/h y vuelve a escribir el coste: sigue en **320 €** (§12.7, paso 5). Crea otro parte con 8 h del primer trabajador: ese cuesta **200 €**.
6. **Investiga.** Cambia temporalmente tu `ZCL_GOR_PARTE_TRABAJO` para que la línea guarde la **referencia** al trabajador y calcule el coste al pedir `coste_total`. Repite el ejercicio 5: ¿qué coste sale tras subir la tarifa? Deshaz el cambio y explica en un comentario de `add_linea` por qué el informe insiste en copiar la tarifa.
